### Apify Actor Configuration

The profiler sends these input params to each actor run:


## Day 2: Vision Analysis Experimentation

**Date**: 2026-03-24
**Objective**: Validate Gemini's ability to understand TikTok content and find the optimal Stage 1 perception prompt.
**Status**: Complete (two experiments run, human evaluation scored)

### Experiment 1 (v1): Prompt Variant Comparison — 15 Items

**Script**: `workbench/scripts/gemini_video_analyzer.py`

**Setup**:
- 15 hand-picked TikToks from Apify run `mCdSJPmsDVb66zATe`
- 10 videos, 2 single images, 3 carousels
- Content: cooking, self-help, comedy, productivity, fan edits, pizza recs, skiing, cinematic, corecore edit, movie review
- Model: `gemini-2.5-flash` (gemini-2.0-flash deprecated during experiment)
- No subtitles or comments in prompts (identified as gap)

**Prompt variants tested** (13 total):
- Thumbnail: T1 (minimal), T2 (structured), T3 (vision-only no metadata), T4 (vision + full metadata)
- Video: V1 (minimal), V2 (comprehensive perception), V3 (sequential multi-pass: visual/audio/entities), V4 (perception + classification hints)
- Slideshow: S1 (cover only), S2 (all images), S3 (first + last)
- Keyframes: K1, K2 (FFmpeg — failed, 0 frames extracted)
- Grounding: with/without Google Search on 5 items

**Results**: 130 experiments, $0.31 total, 1.84M tokens

**Key findings**:

1. **Video >> thumbnail** (12/15 items): thumbnails extracted 0 named entities across all items. Video richness score avg ~120 vs thumbnail ~70. Cost: 24x more ($0.007 vs $0.0003).

2. **V2 (comprehensive perception) is the best prompt**: timestamped scene breakdowns, visual + audio + text + entities. V3 (multi-pass) costs 3x for marginal gain. V4 (hints) adds topic/affect/genre suggestions at zero extra cost — folded into v2.

3. **Metadata helps, doesn't contaminate**: T4 (vision + metadata) > T3 (vision-only). The VISIBLE/INFERRED distinction showed metadata provides context without biasing.

4. **Slideshow: all images essential**: S2 dramatically better for recommendation posts (pizza recs: 37 entities from all images vs 0 from cover). S3 (first + last) captures ~70% at ~40% token cost.

5. **Keyframes failed**: FFmpeg scene detection produced 0 frames for TikTok's codec. Native video input is strictly better.

6. **Grounding sparse**: only 1/5 items triggered (corecore edit, 12 sources). Not worth enabling.

7. **10% parse errors**: 13/130 results had truncated JSON (output token limit 4096 too low).

### Recurring Issues (from founder notes across 44 items)

**Entity extraction gaps**:
- Missing specific entities from carousel slides (restaurant names, product specs, app names)
- Song + artist should be a single searchable entity ("Song by Artist"), not separate
- Recipe ingredients and workout exercises not captured as entities
- TikTok audio metadata frequently mismatches actual audio
- Missing cultural/meme context (Nike ski masks, LinkedIn memes, viral trends)
- Product specifications (model numbers, dimensions) not captured with product entity
- Main topic/opinion/take of the video should be an entity

**Classification issues**:
- "inspiring" massively overassigned — many neutral/informative items mislabeled

- "education" applied too broadly (edits, commentary, advice all get lumped in)

**Perception output issues**:
- 5 items truncated (11%) — long videos exhaust output tokens

### Key Decisions Made

1. **Full video via Gemini File API** — not thumbnails, not keyframes. Confirmed by 12/15 quality wins in v1.
2. **All carousel images** — cover-only misses too much. ~10% decorative images skippable.
3. **Include subtitles + comments in perception prompt** — v1 gap fixed in v2.
4. **Single comprehensive prompt** — multi-pass (V3) not worth 3x cost.
5. **Classification hints in perception** — topic/affect/genre hints folded into Stage 1 at zero extra cost.
6. **max_output_tokens = 8192** — 4096 caused 10% truncation.
7. **Concurrency: 4 for video, 6 for text** — balances speed with Gemini rate limits.

### What Needs Iteration Before Production

1. **Entity extraction** — 51% scored Poor. Needs dedicated entity pass or richer schema. Must capture: searchable song+artist, product specs, recipe ingredients, carousel per-slide entities, main opinion/take.
2. **Affect classification** — "inspiring" overuse, comedy/satire misclassification. May need affect-specific prompt or different approach.
3. **Carousel per-slide extraction** — model often skips slide-by-slide breakdown. Needs stronger prompt instruction or separate per-image pass.
4. **Parse error rate** — 11% truncation on long videos. Need chunking strategy or progressive summarization for videos >120s.
5. **Meme/cultural context** — model has no understanding of current TikTok trends, meme formats, or viral references. May need a grounding/RAG step for cultural context.

### Assumptions for Day 3

1. The V2 perception prompt (with subtitles + comments) is the production Stage 1 baseline — iterate from here.
2. Entity extraction needs a separate focused pass, not just a section in the perception prompt.
3. The 5-facet ontology is the right starting point, but affect labels need revision (reduce "inspiring" dominance).
4. Classification quality is bottlenecked by perception quality — fix perception first, then iterate classification.

### Pipeline v3 Architecture

Two-pass pipeline using `gemini-3-flash-preview`:

**Pass 1: Perception + Entity Extraction** (full video upload)
- Input: video file + caption + hashtags + creator + music metadata + subtitles + top 10 comments
- Output: overall_summary, scene_timeline, entities (name, type, relevance, confidence 1-5), takeaways, audio_identification, structured_content, extraction_confidence
- Entity types: person, place, brand, product, song, artist, movie_or_show, book, app_or_tool, technique, exercise, recipe, clothing, food_item, concept

**Pass 2: Classification** (keyframes + Pass 1 text)
- Input: 3 keyframes + Pass 1 summary/entities/takeaways + metadata
- Output: topic (primary/secondary/micro_labels), genre, affect (tiered: dominant/secondary/minor), viewer_orientation, presentation_style, content_provenance
- Affect uses categorical tiers instead of continuous probabilities (dominant ≥0.6, secondary 0.25-0.59, minor 0.15-0.24)

### End-to-End Tier 1 Runtime Test (100 Fresh Items)

- Semantic search (cosine similarity, OpenAI embeddings)

- Side-by-side raw vs enriched comparison mode

### Key Findings

1. **Vision transforms classification quality.** "inspiring" overassignment 45% → 11%. Fitness false positives eliminated.
2. **Grounding doesn't help for TikTok content.** Model has the video — 5% trigger rate isn't worth 2.6x cost.
3. **Entity extraction is the product.** Users want shoes, restaurants, movies — not classifications. Entity-first agent responses are the right UX.
4. **Tier 1 is viable.** 83% topic agreement, 127s processing. Users can search within minutes of upload.
5. **Apify is the cost bottleneck.** $0.014/item Apify vs $0.005/item all AI combined. Media download is 84% of wall-clock time.
6. **Audio identification is unreliable.** Gemini hallucinated songs on some items. Self-assessment not calibrated. Must weight audio entities lower unless metadata confirms.
7. **Ingestion is the moat.** One-time processing cost creates switching cost. Month 2+ margins are 89-97%.

### Issues Identified

- `startup building` collection maps to `technology` instead of `career` — ontology boundary problem
- Pass 1 may be doing too much (perception + entities + structured content + audio + style) — entity quality may degrade on complex items
- `search_query` and `search_targets` were removed from entity schema per reviewer feedback (query optimization belongs in resolution layer) — need to add back as Pass 3
- Non-English content handling not addressed in prompts
