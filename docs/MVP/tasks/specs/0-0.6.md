### CI/CD Flow
```
PR Opened/Updated:
  → ci.yml triggers
  → Backend: ruff check, pytest
  → Frontend: lint, typecheck, test, build
  → All pass → PR can be merged

Merge to main:
  → deploy-backend.yml → Render
  → deploy-frontend.yml → Vercel
  → deploy-lambdas.yml → AWS
```

## 6) Implementation plan (ordered)

1. Create `.github/workflows/` directory
2. Create `ci.yml` PR validation workflow:
   ```yaml
   name: CI
   on:
     pull_request:
       branches: [main]
   jobs:
     backend:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-python@v5
           with:
             python-version: '3.12'
         - run: cd src/backend && pip install -e ".[dev]"
         - run: cd src/backend && ruff check .
         - run: cd src/backend && ruff format --check .
         - run: cd src/backend && pytest tests/ -v
     frontend:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-node@v4
           with:
             node-version: '20'
         - run: cd src/frontend && npm ci
         - run: cd src/frontend && npm run lint
         - run: cd src/frontend && npm run typecheck
         - run: cd src/frontend && npm test
         - run: cd src/frontend && npm run build
   ```
3. Create `deploy-backend.yml` for Render deployment:
   - Trigger: push to main, changes in src/backend/
   - Use Render deploy hook
4. Create `deploy-frontend.yml` for Vercel deployment:
   - Trigger: push to main, changes in src/frontend/
   - Vercel auto-deploys from GitHub, so this may just verify
5. Create `deploy-lambdas.yml` for AWS SAM deployment:
   - Trigger: push to main, changes in src/lambdas/ or infra/
   - Use AWS credentials from secrets
   - Run `sam build && sam deploy`
6. Create `.github/dependabot.yml` for automated updates
7. Configure GitHub branch protection:
   - Require PR reviews
   - Require status checks to pass
   - Require up-to-date branches
8. Add required secrets to GitHub repository settings:
   - `RENDER_DEPLOY_HOOK_URL`
   - `AWS_ACCESS_KEY_ID`
   - `AWS_SECRET_ACCESS_KEY`
   - `AWS_REGION`
9. Document CI/CD setup in `docs/setup/ci-cd.md`
10. Test workflows with a sample PR
