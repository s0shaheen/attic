# Task 3.7: Lambda: VISION_ANALYSIS

## 0) Outcome

Lambda function `attic-vision-analysis` analyzes video frames, images, and slideshows using GPT-4 Vision to extract visual tags, OCR text, mood, content category, and other enrichment fields.

## 1) Scope

### In-scope
- [ ] Lambda function that calls OpenAI GPT-4 Vision API
- [ ] Batch processing (5 images per API call for efficiency)
- [ ] Extract keyframes from videos (1 frame per 10 seconds, max 5)
- [ ] Process all images for slideshows
- [ ] Process single image for image type
- [ ] Extract: visual_tags, ocr_text, mood_distribution, content_category_distribution, etc.
- [ ] Update media_events with vision analysis results
- [ ] Track cost in processing_steps
- [ ] Use prompt_templates table for versioned prompts

### Out-of-scope / Non-goals
- Video analysis (frame-by-frame only)
- Audio analysis (handled by Whisper)
- Custom model training

## 2) System context

### Components touched
- **Lambda function**: `attic-vision-analysis`
- **Third party**: OpenAI GPT-4 Vision API
- **AWS S3**: Read from temp bucket
- **DB tables**: `media_events`, `processing_steps`, `prompt_templates`
- **Step Functions**: Invoked as Map state (batched)

### Invariants (must always be true)
- Prompt version tracked in processing_steps
- Cost tracked per batch
- All media types (video/image/slideshow) handled appropriately
- OpenAI API key never logged

```python
from pydantic import BaseModel
from uuid import UUID
from typing import Literal

class MediaItemInput(BaseModel):
    media_event_id: UUID
    media_type: Literal["video", "image", "slideshow"]
    s3_video_path: str | None  # For videos (keyframe extraction)
    s3_image_paths: list[str] | None  # For slideshows/images
    s3_thumbnail_path: str | None
    caption_text: str | None  # Context for analysis
    hashtags: list[str] | None

class VisionAnalysisInput(BaseModel):
    upload_id: UUID
    user_id: UUID
    execution_arn: str
    batch_index: int
    media_items: list[MediaItemInput]  # Up to 5 items per batch
```

```sql
    $id, $media_event_id, 'VISION_ANALYSIS', 'openai_gpt4_vision',
    $status, $started_at, $finished_at, $cost_usd, $prompt_version, $output_summary

ON CONFLICT (media_event_id, step_type, attempt) DO UPDATE SET
    status = EXCLUDED.status,
    finished_at = EXCLUDED.finished_at,
    cost_usd = EXCLUDED.cost_usd,
```

## 5) Workflow & state machine (if applicable)

### States
- This Lambda IS a state in the pipeline (AnalyzeVision Map state)
- Receives batches of up to 5 media items

### Idempotency strategy
- Upsert operations for all database writes
- Same images produce same analysis (deterministic prompt)
- Processing tracked by media_event_id

### Failure modes + user-facing behavior
- **OpenAI rate limit**: Retry with exponential backoff
- **OpenAI API error**: Retry, then mark as failed
- **Invalid image**: Skip with warning, continue others
- **Response parsing error**: Log and mark as failed
