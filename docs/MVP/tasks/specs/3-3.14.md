## 3) API contracts (authoritative)

### Error Summary Structure
```python
from pydantic import BaseModel
from datetime import datetime

class StepError(BaseModel):
    step_name: str
    error_type: str  # 'transient' | 'permanent' | 'timeout' | 'rate_limit'
    error_code: str | None  # Vendor-specific error code
    error_message: str
    attempt: int
    timestamp: datetime
    items_affected: int | None

class ErrorSummary(BaseModel):
    status: str  # 'failed' | 'partial_failure'
    total_errors: int
    critical_error: StepError | None  # Error that caused pipeline to stop
    step_errors: list[StepError]  # All errors encountered
    items_failed: int
    items_succeeded: int
    recovery_attempted: bool
    dlq_message_id: str | None
```

## 5) Workflow & state machine (if applicable)

### Error Handling States
```
Any Step → (on error) → HandleError → ClassifyError
    ├── Transient → IncrementRetry → RetryStep
    │                   └── (max retries) → RecordFailure
    ├── Permanent → RecordFailure
    └── Skippable → SkipStep → ContinuePipeline

RecordFailure → IsStepCritical?
    ├── Yes → SendToDLQ → NotifyUser → MarkPipelineFailed
    └── No → IncrementFailedCount → ContinuePipeline
```

### Retry Policies (refined from 3.1)
| Step | Max Retries | Backoff | Jitter | Errors to Retry |
|------|-------------|---------|--------|-----------------|
| PARSE_EXPORT | 3 | 2x | 10% | All |
| APIFY_ENRICH | 5 | 2x | 20% | rate_limit, timeout, 5xx |
| MEDIA_DOWNLOAD | 3 | 2x | 10% | timeout, connection |
| SUBTITLE_FETCH | 2 | 2x | 10% | timeout, 5xx |
| WHISPER_TRANSCRIBE | 3 | 2x | 10% | rate_limit, timeout |
| VISION_ANALYSIS | 3 | 2x | 10% | rate_limit, timeout |
| TEXT_FUSION | 2 | 2x | 10% | database |
| EMBEDDING | 3 | 2x | 10% | rate_limit, timeout |
| DERIVED_FIELDS | 2 | 2x | 10% | database |
| SEARCH_INDEX | 2 | 2x | 10% | database |

### Failure modes + user-facing behavior
- **Single item failure (non-critical)**: Log, increment counter, continue
- **Batch failure (non-critical)**: Retry batch, then skip items
- **Critical step failure**: Stop pipeline, notify user, send to DLQ
- **Partial success**: Mark as 'complete_with_errors', show user what failed
