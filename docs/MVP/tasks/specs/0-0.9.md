# Task 0.9: Staging Environment

## 0) Outcome

A complete staging environment mirrors production with separate Supabase project, Render backend, Vercel frontend deployment, and AWS resources. Developers can test changes end-to-end before production deployment, with automated smoke tests validating deployments.

## 1) Scope

### In-scope
- [ ] Create staging Supabase project with separate database
- [ ] Configure Render staging environment for backend
- [ ] Configure Vercel staging deployment (preview branches)
- [ ] Create staging AWS resources (separate Step Functions, Lambda, S3, SQS)
- [ ] Set up staging environment variables and secrets
- [ ] Create smoke test suite for deployment validation
- [ ] Configure staging-specific rate limits and quotas
- [ ] Document staging access and deployment process

### Out-of-scope / Non-goals
- Production environment setup (separate task)
- Load testing infrastructure (Task 9.7)
- Blue-green deployment (future enhancement)
- Multiple staging environments (one is sufficient for MVP)

## 6) Implementation plan (ordered)

1. **Create Staging Supabase Project**
   - Create new project in Supabase dashboard (name: attic-staging)
   - Enable pgvector extension
   - Run Alembic migrations
   - Create Storage bucket
   - Note: Use separate org or clearly label as staging

2. **Configure Render Staging**
   - Create new Web Service in Render
   - Name: `attic-api-staging`
   - Connect to GitHub repo
   - Set branch: `main` (or `staging` if using staging branch)
   - Configure environment variables (staging values)
   - Set auto-deploy on push

3. **Configure Vercel Staging**
   - Vercel automatically creates preview deployments
   - Configure staging domain alias if desired
   - Set environment variables for staging
   - Configure preview deployment settings

4. **Deploy Staging AWS Resources**
   - Create `infra/staging/samconfig.toml`:
     ```toml
     [default.deploy.parameters]
     stack_name = "attic-staging"
     s3_bucket = "attic-sam-staging"
     s3_prefix = "attic-staging"
     region = "us-east-1"
     capabilities = "CAPABILITY_IAM"
     parameter_overrides = "Environment=staging"
     ```
   - Deploy: `sam deploy --config-file infra/staging/samconfig.toml`

5. **Set Up Third-Party Test Accounts**
   - Stripe: Use test mode keys (sk_test_*, pk_test_*)
   - Apify: Use development/test token if available
   - OpenAI: Consider using lower-tier model for staging
   - Resend: Use test mode or sandbox
   - Sentry: Create staging project
   - PostHog: Create staging project

6. **Create Smoke Test Suite**
   - `scripts/smoke-tests/run.sh` - Orchestrates all tests
   - Tests to include:
     ```bash
     # Health checks
     curl -f $BACKEND_URL/health
     curl -f $FRONTEND_URL

     # Auth flow (requires test user)
     # Upload flow (requires test file)
     # Pipeline trigger (verify SQS message sent)
     ```

7. **Create Deployment Workflow**
   ```yaml
   # .github/workflows/deploy-staging.yml
   name: Deploy to Staging
   on:
     push:
       branches: [main]
   jobs:
     deploy:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         # Deploy backend (Render auto-deploys)
         # Deploy lambdas
         - run: sam deploy --config-file infra/staging/samconfig.toml
         # Run smoke tests
         - run: ./scripts/smoke-tests/run.sh
   ```

8. **Document Staging Environment**
   - Access URLs
   - Credentials location (1Password, GitHub Secrets)
   - Deployment process
   - How to access logs
   - How to reset staging data

9. **Configure Staging Limits**
   - Lower rate limits for cost control
   - Smaller upload limits
   - Test tier limits only

10. **Verify End-to-End**
    - Deploy all components
    - Run smoke tests
    - Test manual upload flow
    - Verify logs in all services
