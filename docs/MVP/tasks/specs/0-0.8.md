# Task 0.8: Environment Configuration

## 0) Outcome

Environment variables and secrets are properly structured across all environments (local, staging, production). Developers can easily configure the application without exposing sensitive credentials, and the configuration is validated at startup.

## 1) Scope

### In-scope
- [ ] Define environment variable schema for all services
- [ ] Create `.env.example` files with all required variables documented
- [ ] Implement configuration validation at application startup
- [ ] Set up secrets management strategy (env vars + cloud secrets)

### Out-of-scope / Non-goals

## 6) Implementation plan (ordered)

1. Create root `.env.example` listing all variables (no values)
2. Create `src/backend/app/config.py` with Pydantic Settings:
   ```python
   from pydantic_settings import BaseSettings, SettingsConfigDict

   class Settings(BaseSettings):
       model_config = SettingsConfigDict(env_file=".env", env_file_encoding="utf-8")

       # Database
       database_url: str
       supabase_url: str
       supabase_service_key: str

       # AWS
       aws_access_key_id: str
       aws_secret_access_key: str
       aws_region: str = "us-east-1"
       aws_endpoint_url: str | None = None  # LocalStack

       # Third-party
       apify_api_token: str
       openai_api_key: str

       # Payments
       stripe_secret_key: str
       stripe_webhook_secret: str

       # Notifications
       resend_api_key: str

       # Observability
       sentry_dsn: str | None = None
       posthog_api_key: str | None = None

       # Application
       environment: str = "development"
       log_level: str = "INFO"
       cors_origins: list[str] = ["http://localhost:3000"]

   settings = Settings()
   ```
3. Update `src/backend/app/main.py` to import settings (validates on load)
4. Create `src/frontend/lib/env.ts` with Zod validation:
   ```typescript
   import { z } from 'zod';

   const envSchema = z.object({
     NEXT_PUBLIC_SUPABASE_URL: z.string().url(),
     NEXT_PUBLIC_SUPABASE_ANON_KEY: z.string(),
     NEXT_PUBLIC_API_URL: z.string().url(),
     NEXT_PUBLIC_POSTHOG_KEY: z.string().optional(),
     NEXT_PUBLIC_SENTRY_DSN: z.string().optional(),
     NEXT_PUBLIC_ENVIRONMENT: z.enum(['development', 'staging', 'production']),
   });

   export const env = envSchema.parse({
     NEXT_PUBLIC_SUPABASE_URL: process.env.NEXT_PUBLIC_SUPABASE_URL,
     // ... etc
   });
   ```
5. Create `src/backend/.env.example` with documentation comments
6. Create `src/frontend/.env.example` with documentation comments
7. Create `src/lambdas/.env.example` for Lambda-specific config
8. Update `.gitignore` to exclude all `.env*` except `.env.example`
9. Document all variables in `docs/setup/environment.md`:
   - Variable name
   - Description
   - Required/Optional
   - Where to obtain (e.g., "Supabase Dashboard > Settings > API")
   - Example value format
10. Test: Remove `.env`, verify application fails with clear error
