# Task 1.6: Account Deletion Flow

## 0) Outcome

Users can request deletion of their account and all associated data. The deletion completes within 24 hours (per PRD requirement), removes all user data from the database and storage, and provides confirmation. This satisfies GDPR right-to-erasure requirements.

## 1) Scope

### In-scope
- [ ] Create "Delete Account" button in settings page
- [ ] Create confirmation modal with clear warning about data loss
- [ ] Create backend endpoint to initiate account deletion
- [ ] Delete user's data from all tables (uploads, media_events, processing_steps)
- [ ] Delete user's files from Supabase Storage
- [ ] Delete user from Supabase Auth (auth.users)
- [ ] Sign out user after deletion request
- [ ] Send confirmation email after deletion complete (via Resend)
- [ ] Log deletion for audit purposes

### Out-of-scope / Non-goals
- Immediate deletion (24-hour window per PRD for async processing)
- Data export before deletion (nice-to-have, not MVP)
- Soft delete / recovery period
- Canceling a deletion request after confirmation
- Admin-initiated deletion

## 3) API contracts (authoritative)

### DELETE /api/user/me

**Request:**
No body required. User ID derived from JWT.

**Response (202 Accepted):**
```json
{
  "message": "Account deletion initiated",
  "deletion_scheduled_at": "2026-01-29T10:00:00Z",
  "confirmation_email_sent": true
}
```

### Pydantic Models

```python
from pydantic import BaseModel
from datetime import datetime

class AccountDeletionResponse(BaseModel):
    message: str
    deletion_scheduled_at: datetime
    confirmation_email_sent: bool

class AccountDeletionError(BaseModel):
    detail: str
    code: str
```

### Status codes
- `202 Accepted` - Deletion initiated successfully
- `401 Unauthorized` - Not authenticated
- `500 Internal Server Error` - Deletion failed

### Auth requirements
- Required: Valid Supabase JWT
- User can only delete their own account

## 4) Data model changes

No new tables. Deletion cascades through existing foreign keys:

### Deletion Order (to respect FK constraints)
```sql
-- 1. Delete processing_steps (FK to media_events)
DELETE FROM processing_steps
WHERE media_event_id IN (
  SELECT id FROM media_events WHERE user_id = $1
);

-- 2. Delete media_events (FK to uploads, users)
DELETE FROM media_events WHERE user_id = $1;

-- 3. Delete upload_pipeline_runs (FK to uploads)
DELETE FROM upload_pipeline_runs WHERE user_id = $1;

-- 4. Delete uploads (FK to users)
DELETE FROM uploads WHERE user_id = $1;

-- 5. Delete user profile data (if separate table exists)
-- N/A for MVP - user data is in auth.users

-- 6. Delete from auth.users via Supabase Admin API
```

### RLS Considerations
- Deletion must use service role key to bypass RLS
- Or use RLS policies that allow users to delete their own data

## 5) Workflow & state machine

### Deletion Flow
1. **User Action**: User clicks "Delete Account" in settings
2. **Confirmation**: Modal warns about permanent data loss
3. **API Call**: Frontend calls `DELETE /api/user/me`
4. **Backend Processing**:
   - Validate user is authenticated
   - Delete Storage files
   - Delete database records (in order)
   - Delete from Supabase Auth
   - Queue confirmation email
5. **Response**: Return 202 Accepted
6. **Sign Out**: Frontend signs out user
7. **Redirect**: Redirect to login or landing page
8. **Email**: Send confirmation email (async via Resend)

### Error Handling
- Partial deletion failure: Log error, continue with remaining deletions
- Storage deletion failure: Log and continue (data is orphaned but not accessible)
- Database deletion failure: Roll back if possible, return error
- Auth deletion failure: User remains in auth.users but has no data (acceptable)

## 7) Observability & analytics

### Logs (required fields)
- Deletion initiated: `{ event: "account_deletion_initiated", user_id, timestamp }`
- Deletion step: `{ event: "deletion_step", step: "storage|media_events|uploads|auth", user_id, success: boolean }`
- Deletion complete: `{ event: "account_deletion_complete", user_id, duration_ms }`
