## 3) API contracts (authoritative)

N/A - This task is configuration only. The OAuth flow is handled entirely by Supabase Auth.

### OAuth Flow (reference)
```
1. User clicks "Sign in with Google"
2. Redirect to: https://<project>.supabase.co/auth/v1/authorize?provider=google
3. User authenticates with Google
4. Google redirects to: <redirect_uri>?code=<auth_code>
5. Supabase exchanges code for tokens
6. Supabase creates/updates user in auth.users
7. Redirect to app with session
```

### Supabase Auth Endpoints (managed by Supabase)
- `POST /auth/v1/token` - Exchange auth code for tokens
- `POST /auth/v1/logout` - Sign out
- `GET /auth/v1/user` - Get current user

## 6) Implementation plan (ordered)

1. **Google Cloud Console Setup**
   - Create or select Google Cloud project
   - Enable Google+ API (or People API)
   - Create OAuth 2.0 credentials (Web application type)
   - Add authorized JavaScript origins:
     - `http://localhost:3000` (local dev)
     - `https://attic.app` (production)
   - Add authorized redirect URIs:
     - `http://localhost:54321/auth/v1/callback` (local Supabase)
     - `https://<project-ref>.supabase.co/auth/v1/callback` (production)

2. **Supabase Dashboard Configuration**
   - Navigate to Authentication > Providers
   - Enable Google provider
   - Enter Client ID and Client Secret from Google Cloud Console
   - Save configuration

3. **Environment Configuration**
   - Add to `.env.local` (frontend):
     ```
     NEXT_PUBLIC_SUPABASE_URL=<your-supabase-url>
     NEXT_PUBLIC_SUPABASE_ANON_KEY=<your-anon-key>
     ```
   - Add to `.env` (backend, if needed for JWT verification):
     ```
     SUPABASE_URL=<your-supabase-url>
     SUPABASE_SERVICE_ROLE_KEY=<your-service-role-key>
     SUPABASE_JWT_SECRET=<your-jwt-secret>
     ```

4. **Create Setup Documentation**
   - Document step-by-step process in `docs/setup/GOOGLE_OAUTH_SETUP.md`
   - Include screenshots or clear instructions
   - List all required environment variables

5. **Verify OAuth Flow**
   - Test via Supabase Dashboard Auth UI
   - Confirm user appears in auth.users table after sign-in
   - Verify user metadata is populated correctly
