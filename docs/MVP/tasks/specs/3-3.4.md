# Task 3.4: Lambda: MEDIA_DOWNLOAD

## 0) Outcome

Lambda function `attic-media-download` downloads video files, images, or slideshow images from TikTok to S3 temporary storage for subsequent vision analysis and transcription.

## 1) Scope

### In-scope
- [ ] Lambda function that downloads media based on media_type
- [ ] Download video files for video type
- [ ] Download all images for slideshow type
- [ ] Download single image for image type
- [ ] Store in S3 temp bucket with structured paths
- [ ] Handle TikTok CDN quirks (redirects, rate limits)
- [ ] Track download status in processing_steps
- [ ] Return S3 paths for next pipeline step
- [ ] Set TTL on S3 objects (auto-delete after 24 hours)

### Out-of-scope / Non-goals
- Subtitle download (task 3.5)
- Video transcription (task 3.6)
- Vision analysis (task 3.7)
- Long-term media storage (derived artifacts only)

## 2) System context

### Components touched
- **Lambda function**: `attic-media-download`
- **AWS S3**: Temp bucket `attic-media-temp`
- **DB tables**: `media_events`, `processing_steps`
- **Step Functions**: Invoked as Map state

### Invariants (must always be true)
- S3 objects have TTL (lifecycle policy deletes after 24h)
- Download errors don't block other items
- S3 paths are deterministic for idempotency
- No PII in S3 object keys

### Lambda Output
```python
from pydantic import BaseModel
from uuid import UUID
from typing import Literal

class DownloadedMedia(BaseModel):
    media_event_id: UUID
    status: Literal["downloaded", "failed"]
    media_type: Literal["video", "image", "slideshow"]
    s3_video_path: str | None = None  # For videos
    s3_image_paths: list[str] | None = None  # For slideshows/images
    s3_thumbnail_path: str | None = None
    file_size_bytes: int | None = None
    error_message: str | None = None

class MediaDownloadOutput(BaseModel):
    upload_id: UUID
    items_downloaded: int
    items_failed: int
    downloaded_items: list[DownloadedMedia]
    total_bytes: int
```

## 4) Data model changes

### media_events updates
```sql
-- Add columns for S3 paths if not exists
ALTER TABLE media_events ADD COLUMN IF NOT EXISTS s3_video_path TEXT;
ALTER TABLE media_events ADD COLUMN IF NOT EXISTS s3_image_paths TEXT[];
ALTER TABLE media_events ADD COLUMN IF NOT EXISTS s3_thumbnail_path TEXT;
ALTER TABLE media_events ADD COLUMN IF NOT EXISTS image_count INT;

UPDATE media_events SET
    s3_video_path = $s3_video_path,
    s3_image_paths = $s3_image_paths,
    s3_thumbnail_path = $s3_thumbnail_path,
    image_count = $image_count,
    processing_substate = 'media_downloaded',
    updated_at = NOW()
WHERE id = $media_event_id;
```

### processing_steps insert
```sql
INSERT INTO processing_steps (
    id, media_event_id, step_type, provider, status,
    started_at, finished_at, output_summary
) VALUES (
    $id, $media_event_id, 'MEDIA_DOWNLOAD', 'aws_s3',
    $status, $started_at, $finished_at, $output_summary
)
ON CONFLICT (media_event_id, step_type, attempt) DO UPDATE SET
    status = EXCLUDED.status,
    finished_at = EXCLUDED.finished_at,
    output_summary = EXCLUDED.output_summary;
```

## 5) Workflow & state machine (if applicable)

### States
- This Lambda IS a state in the pipeline (DownloadMedia Map state)

### Idempotency strategy
- Deterministic S3 paths based on upload_id and media_event_id
- S3 PutObject is idempotent (overwrites existing)
- Check if object exists before downloading (optimization)

### Failure modes + user-facing behavior
- **TikTok CDN error**: Retry with backoff
- **Video removed from TikTok**: Mark as failed, continue others
- **S3 error**: Retry with backoff
- **Timeout on large video**: Increase Lambda timeout, or skip
