# Task 2.6: Scope Selection API

## 0) Outcome

Users can select which videos to process from their TikTok export (liked only, favorited only, or both). The API validates scope selection against user's tier limits and updates the upload record. This determines which videos enter the processing pipeline.

## 3) API contracts (authoritative)

### Request/Response

```python
# src/backend/app/schemas/uploads.py
from pydantic import BaseModel, Field
from uuid import UUID
from typing import Literal
from datetime import datetime

class ScopeSelectionRequest(BaseModel):
    """Request to set the processing scope."""
    scope: Literal["liked", "favorited", "both"] = Field(
        ...,
        description="Which videos to process"
    )

class ScopeSelectionResponse(BaseModel):
    """Response after scope selection."""
    upload_id: UUID
    scope: str
    total_items: int = Field(..., description="Number of items to process")
    liked_count: int = Field(..., description="Liked videos in selection")
    favorited_count: int = Field(..., description="Favorited videos in selection")
    tier_limit: int = Field(..., description="User's tier video limit")
    within_limit: bool = Field(..., description="Selection fits within tier limit")
    estimated_processing_minutes: int = Field(
        ...,
        description="Estimated time to complete processing"
    )
    ready_for_consent: bool = Field(
        ...,
        description="Whether upload is ready for consent capture"
    )

class TierLimitExceededError(BaseModel):
    """Error response when scope exceeds tier limit."""
    error: str = "TIER_LIMIT_EXCEEDED"
    message: str
    selected_count: int
    tier_limit: int
    tier: str
    upgrade_required: bool = True
```

### Status codes
- `200 OK` - Scope set successfully
- `400 Bad Request` - Invalid scope value
- `401 Unauthorized` - Missing or invalid auth
- `403 Forbidden` - Upload belongs to different user
- `404 Not Found` - Upload ID not found
- `409 Conflict` - Upload already processing or scope exceeds limit
- `422 Unprocessable Entity` - Upload not validated yet

### Auth requirements
- Required: Supabase JWT
- User must own the upload

### Processing Time Estimate Logic

```python
# Estimation: ~0.5 seconds per video average across all steps
# 1000 videos ≈ 10-15 minutes (per PRD performance requirements)
def estimate_processing_minutes(total_items: int) -> int:
    base_minutes = max(1, total_items // 100)  # ~1 minute per 100 videos
    buffer = base_minutes * 0.3  # 30% buffer for variability
    return int(base_minutes + buffer)
```

## 5) Workflow & state machine

### Upload States
- `validated` → `scope_selected`: When scope is set
- `scope_selected` → `consented`: After consent captured (Task 2.7)
- `consented` → `processing`: When pipeline starts

### Scope Selection Flow
1. Upload validated (status = "validated")
2. User selects scope
3. API validates against tier limits
4. If within limit: update upload, return success
5. If exceeds limit: return 409 with upgrade info
6. Upload status becomes "scope_selected"
7. Frontend shows consent screen (Task 2.7)

### Scope Change Rules
- Can change scope while status is "validated" or "scope_selected"
- Cannot change after "consented" or "processing"
