## 4) Data model changes

### media_events updates
```sql
-- Update processing state to complete
UPDATE media_events SET
    processing_state = 'complete',
    processing_substate = NULL,
    updated_at = NOW()
WHERE id = ANY($media_event_ids)
  AND full_text IS NOT NULL;

-- For items without full_text, still mark complete but note
UPDATE media_events SET
    processing_state = 'complete',
    processing_substate = 'no_text_content',
    updated_at = NOW()
WHERE id = ANY($media_event_ids)
  AND full_text IS NULL;
```

### upload_pipeline_runs updates
```sql
UPDATE upload_pipeline_runs SET
    videos_complete = videos_complete + $items_indexed,
    updated_at = NOW()
WHERE upload_id = $upload_id;
```

### processing_steps insert
```sql
INSERT INTO processing_steps (
    id, media_event_id, step_type, provider, status,
    started_at, finished_at, output_summary
) VALUES (
    $id, $media_event_id, 'SEARCH_INDEX', 'postgresql',
    $status, $started_at, $finished_at, $output_summary
)
ON CONFLICT (media_event_id, step_type, attempt) DO UPDATE SET
    status = EXCLUDED.status,
    finished_at = EXCLUDED.finished_at,
    output_summary = EXCLUDED.output_summary;
```

## 5) Workflow & state machine (if applicable)

### States
- This Lambda IS a state in the pipeline (UpdateSearchIndex Map state)
- Final processing step before FinalizeUpload

### Idempotency strategy
- Setting processing_state = 'complete' is idempotent
- Counter increments use transactions to prevent double-counting
- Upsert operations for processing_steps

### Failure modes + user-facing behavior
- **Database error**: Retry with backoff
- **Index not available**: Log warning (rare, indexes created in migration)
