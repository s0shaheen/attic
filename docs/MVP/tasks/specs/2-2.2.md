# Task 2.2: Presigned URL API

## 0) Outcome

The backend provides an API endpoint that generates short-lived presigned URLs for uploading TikTok export ZIPs directly to Supabase Storage. This enables secure, direct-to-storage uploads without proxying file data through the API server.

## 1) Scope

### In-scope
- [ ] Create `POST /api/uploads/presigned-url` endpoint
- [ ] Generate Supabase Storage presigned upload URL
- [ ] Create upload record in database with `pending` status
- [ ] Return presigned URL, upload_id, and expiration time
- [ ] Validate user is authenticated
- [ ] Enforce tier-based upload limits (check existing uploads count)

### Out-of-scope / Non-goals

- Frontend Uppy integration (Task 2.3)
- File parsing logic (Task 2.4)
- Multipart upload handling (Supabase handles this)

## 3) API contracts (authoritative)

### Request/Response

```python
# src/backend/app/schemas/uploads.py
from pydantic import BaseModel, Field
from uuid import UUID
from datetime import datetime

class PresignedUrlRequest(BaseModel):
    """Request to generate a presigned upload URL."""
    filename: str = Field(..., description="Original filename for reference", max_length=255)
    content_type: str = Field(
        default="application/zip",
        description="MIME type of the file"
    )

class PresignedUrlResponse(BaseModel):
    """Response containing the presigned URL and upload metadata."""
    upload_id: UUID = Field(..., description="Unique identifier for this upload")
    presigned_url: str = Field(..., description="URL to upload file to")
    storage_path: str = Field(..., description="Path in storage bucket")
    expires_at: datetime = Field(..., description="When the presigned URL expires")
    max_file_size: int = Field(..., description="Maximum allowed file size in bytes")

class UploadRecord(BaseModel):
    """Upload record in database."""
    id: UUID
    user_id: UUID
    source_platform: str = "tiktok"
    scope: str | None = None  # Set later via scope selection
    status: str = "pending"
    storage_path: str
    original_filename: str
    created_at: datetime
```

```typescript
// src/frontend/lib/api/uploads.ts
import { z } from 'zod';

export const presignedUrlRequestSchema = z.object({
  filename: z.string().max(255),
  content_type: z.string().default('application/zip'),
});

export const presignedUrlResponseSchema = z.object({
  upload_id: z.string().uuid(),
  presigned_url: z.string().url(),
  storage_path: z.string(),
  expires_at: z.string().datetime(),
  max_file_size: z.number(),
});

export type PresignedUrlRequest = z.infer<typeof presignedUrlRequestSchema>;
export type PresignedUrlResponse = z.infer<typeof presignedUrlResponseSchema>;
```

### Status codes
- `200 OK` - Presigned URL generated successfully
- `400 Bad Request` - Invalid content type or filename
- `401 Unauthorized` - Missing or invalid Supabase JWT
- `403 Forbidden` - User has reached upload limit for their tier
- `500 Internal Server Error` - Failed to generate presigned URL

### Auth requirements
- Required: Supabase JWT in Authorization header
- user_id derived from token, never from client

## 5) Workflow & state machine

### Upload States
- `pending` - Presigned URL issued, awaiting file upload
- `uploaded` - File uploaded to storage, awaiting processing
- `processing` - Pipeline running
- `complete` - Pipeline finished successfully
- `failed` - Pipeline failed

### Transitions (this task)
- (none) → `pending`: When presigned URL is generated

### Presigned URL Lifecycle
1. User requests presigned URL
2. Backend creates upload record with `pending` status
3. Backend generates presigned URL (valid for 1 hour)
4. User uploads file directly to Supabase Storage
5. S3/Storage event triggers processing (Task 3.12)
